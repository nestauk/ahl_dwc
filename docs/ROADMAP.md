# Roadmap

What should happen next in `ahl_dwc`, in the order it should happen, and the dependency that forces
each position. Written against the worktree at `fix/gcc-cpp-compat` (tip `2f46f9d`), with
`origin/main` at `e63a2ce`.

Every item here is motivated by something recorded in the repository — an open issue or PR, a
comment in a workflow or source file, or a gap the [ADRs](adr/) and [runbooks](runbooks/) had to
write down as unverified. Nothing is here because it seemed like a good idea.

**Effort figures are estimates**, in engineer-days for one engineer familiar with the repo,
including review. They are not derived from repository evidence and should be treated as sizing, not
commitments.

Ordering rule used throughout: a phase may not start until the phase above it is done, because each
one either changes the ground the next stands on (Phase 0), or produces the evidence the next needs
in order to be safe (Phase 2 before Phase 5).

## Phase 2 — Widen the regression suite

The current suite is 15 test functions parameterised to 30 collected tests, with four golden final
weights. That is enough to catch a gross regression and not enough to certify a change to the
numerics. This phase is the precondition for Phases 3 and 5, and it is the one item that is worth
doing under every possible future — including deciding never to port to Rust.

## Cross-cutting: what this roadmap does not contain

- **A pinned, portable normal distribution** (item (c2) of [`rust-port.md`](rust-port.md), 1–2 days)
  is genuinely optional. It would make Brownian output value-pinnable, which is a real improvement,
  but it changes existing Brownian output for existing users. Do it only if a downstream analysis
  needs reproducible Brownian paths; otherwise the seed-only tests are an honest description of what
  the C++ can promise.
- **Fixing the `days` off-by-one step** (`days=365` gives `Time[-1] == 364.0`). This is inherited
  upstream behaviour and all four goldens bake it in. Changing it means diverging from `bw`, which
  the [upstream C++ rule](../CONTRIBUTING.md#the-upstream-c-rule) forbids without an issue and an
  ADR. Raise it with `INSP-RH/bw` instead.
- **Windows support.** No CI leg, no wheel, and no recorded user need.
